# Pack to Pack QMS — نظام إدارة الجودة

تطبيق ويب حديث (React + Vite + Tailwind) لإدارة الجودة (QMS) في مصنع حقن بلاستيك
متخصص في عبوات الأغذية (جبن وحلويات)، مصمم خصيصاً لمهندس/مفتش الجودة في خط الإنتاج.

## ✨ الميزات
- لوحة تحكم بمؤشرات KPI لحظية + تنبيه ذكي عند تجاوز معدل الرفض 3%
- تحليل باريتو للعيوب الأكثر تكراراً + توزيع قرارات الجودة (Chart.js)
- نموذج فحص جودة متوافق مع الهاتف (Mobile-First) مع:
  - اختيار العيوب ودرجة الخطورة (حرج / رئيسي / فرعي)
  - رفع/التقاط صورة للعيب مع ضغط تلقائي
  - إملاء صوتي للملاحظات بالعربية (Web Speech API)
- متابعة الحالات المفتوحة (CAPA) مع تحديث الحالة والفني والإجراء المتخذ
- تصدير: PDF احترافي بالعربية (pdfmake)، Excel منظم (SheetJS)، ومشاركة واتساب
- نسخ احتياطي/استرجاع JSON، ودعم PWA للعمل بدون إنترنت داخل المصنع
- طبقة Data Adapter جاهزة للتحويل لاحقاً إلى Supabase أو Firebase دون تعديل الواجهات

## 🚀 التشغيل محلياً
```bash
npm install
npm run dev
```
سيعمل التطبيق على: http://localhost:5173

## 📦 بناء نسخة الإنتاج (Production Build)
```bash
npm run build
npm run preview
```
الناتج داخل مجلد `dist/` جاهز للنشر على أي استضافة (Netlify, Vercel, Nginx...).

## 📱 تثبيت كتطبيق (PWA) على أجهزة المفتشين
بعد بناء ونشر التطبيق (يجب أن يكون عبر HTTPS)، افتحه من متصفح الهاتف (Chrome/Safari)
واختر "إضافة إلى الشاشة الرئيسية / Add to Home Screen". سيعمل بعدها بدون إنترنت
بفضل Service Worker المُفعّل تلقائياً عبر `vite-plugin-pwa`.

> ملاحظة: في وضع التطوير (`npm run dev`) يعمل الـ Service Worker بشكل محدود؛
> للتجربة الكاملة لوضع Offline استخدم `npm run build && npm run preview`.

## 🖋️ تفعيل الخط العربي داخل تقارير PDF (خطوة مهمة)
مكتبة `pdfmake` لا تدعم افتراضياً عرض الحروف العربية بجودة عالية. لتفعيل خط عربي
احترافي (مثل Amiri) في تقارير الـ PDF:

1. نزّل خط [Amiri](https://fonts.google.com/specimen/Amiri) بصيغة `.ttf`
   (`Amiri-Regular.ttf` و `Amiri-Bold.ttf`)
2. ضع الملفين في `src/assets/fonts/`
3. حوّلهما إلى Base64 (عبر أداة pdfmake الرسمية لبناء الخطوط، راجع التعليمات
   داخل `src/utils/pdfFonts.js`)
4. الصق الناتج داخل `src/utils/arabicFontVfs.js` بنفس الصيغة الموضحة في الملف
5. أعد تشغيل المشروع — سيتحول التصدير تلقائياً لاستخدام الخط العربي في كل التقارير

قبل تنفيذ هذه الخطوة سيعمل تصدير PDF بشكل طبيعي (تخطيط، جداول، رسوم بيانية،
تواقيع) لكن قد لا تظهر الحروف العربية بأفضل جودة إخراج داخل ملف PDF فقط، بينما
تبقى صحيحة تماماً على الشاشة، وفي Excel، وفي رسائل واتساب.

## 🔄 الترحيل لاحقاً إلى Supabase / Firebase
كل عمليات القراءة/الكتابة تمر عبر `src/utils/dataAdapter.js` فقط. لتفعيل قاعدة
بيانات سحابية بدلاً من `localStorage`:
- استبدل تنفيذ الدوال الموجودة في هذا الملف فقط (نفس الأسماء والتوقيعات) باستدعاءات
  Supabase (`supabase.from('inspections')...`) أو Firestore.
- لا حاجة لتعديل أي مكوّن (Component) آخر في التطبيق.

## 🗂️ هيكل المشروع
```
src/
  components/
    Layout/       # الشريط الجانبي والهيدر
    Dashboard/    # لوحة التحكم والمخططات
    Inspection/   # نموذج تسجيل الفحص
    Capa/         # متابعة الحالات المفتوحة
    Reports/      # الفلترة والتصدير
    Backup/       # النسخ الاحتياطي والإعدادات
  context/        # AppContext - الحالة العامة والـ KPIs
  data/           # ثوابت النظام (ماكينات، منتجات، عيوب...)
  utils/          # dataAdapter, pdfExport, excelExport, whatsapp, speechToText...
```

## 🏭 تخصيص البيانات
جميع القوائم (عدد الماكينات، أسماء المنتجات، أنواع الخامات، أنواع العيوب) موجودة
في ملف واحد: `src/data/constants.js` ويمكن تعديلها مباشرة لتناسب خط إنتاجك.
